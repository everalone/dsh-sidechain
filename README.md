# dsh-sidechain

DSH 侧会话插件：在**临时 fork** 的独立会话中执行任务——侧会话继承主会话的已完成上下文作为参考，但**不写入主会话历史**，主线程不受影响、继续运行。插件提供两种侧会话模式：

| 模式 | 命令 | 语义 | 风格 |
|---|---|---|---|
| **持续性侧会话** | `/side <问题>` | 创建可续聊的侧线程，子代理在后台持续工作，可随时继续对话，直到任务完成 | Codex side conversation |
| **一次性侧问** | `/btw <问题>` | 单个问题、单个回答，答案显示在侧链面板，用完即止；主会话输入不被占用 | Claude 式侧聊（不阻塞） |

> 注：Codex 上 `/btw` 与 `/side` 行为相同（均为持续性侧会话）；本插件刻意区分二者——`/side` 为持续性侧线程，`/btw` 为一次性问答。两者都不阻塞主会话：命令立即返回，子代理在后台运行，对话在右侧链面板流式呈现。

| 命令 | 行为 |
|---|---|
| `/side <问题>` | 创建可续聊的命名侧线程（持续性） |
| `/side list` | 列出本会话的全部直接子代理 |
| `/btw <问题>` | 一次性侧问：命令立即返回，答案在侧链面板查看 |

## 安装

前置：DSH 快照（含 `lib/`）+ `dsh web` 运行中。依赖插件（`dsh-subagent`、`dsh-subagent-fork`、`dsh-commands`）默认 profile 已含，无需额外安装。

> 兼容性：适配 DSH **0810** 快照（客户端插件声明使用 `dsh.client` 字段；0809 及更早的 `dshClient` 字段已不被 0810 读取）。

```sh
git clone https://github.com/dsh-external/dsh-sidechain.git
cd dsh-sidechain && pnpm install
dsh plugin --profile web add link:/path/to/dsh-sidechain
```

配置行（`$DSH_HOME/profiles/web/cordis.patch.yml`）：

```yaml
- insert:
    - id: dsh-sidechain
      name: '@dsh-external/dsh-sidechain'
```

> 配置行的新增/移除热生效、无需重启；插件代码更新需重启 `dsh web` 并刷新页面。

## 配置

| Key | 默认 | 说明 |
|---|---|---|
| `providerName` | `fork` | `ctx.subagents` 上的 provider 名 |
| `persona` | 内置侧会话 persona | 侧会话行为约束（只读探索、不主动改文件、禁子代理）；空字符串 = 不覆盖部署 persona |
| `readOnlyTools` | 无 | 侧会话工具 allow-list（如 `["read","grep","glob"]`）；缺省不限制 |

> **热卸载与重挂**：从 `cordis.patch.yml` 移除本插件的配置行并保存即卸载，无需重启——服务端即时生效（`/side`、`/btw` 从命令列表消失）；客户端清单同步更新，已打开的页面刷新后侧链面板随之移除（刷新前命令已不可用）。把配置行加回并保存即重挂，命令即时恢复，页面刷新后面板恢复。插件代码更新（`lib/`）不在此列，仍需重启 `dsh web` 并刷新页面。

## 使用

- `/side 调研一下 session-query 的 FTS 索引` —— 持续性侧会话：创建可续聊的命名侧线程，侧线程在后台持续工作，对话显示在右侧链面板，主会话保持不变
- `/side 帮我分析这段实现` —— 创建可持续追问的侧线程
- `/side list` —— 列出本会话的全部直接子代理
- `/btw 这个目录下哪个文件最大？` —— 一次性侧问：命令立即返回（主会话不阻塞），答案在右侧链面板流式查看；如需多轮，请用 `/side`

## 侧链面板

会话标题行新增**侧链按钮**（🌿 图标）：点击在 Web UI **右侧**打开一个浮动侧边栏，列出当前会话的子代理。

- **列表**：每行显示子代理标题、类型（`/side 可续聊` / `/btw 一次性`）、运行状态（运行中/已结束）；标题行按钮带运行中数量角标；运行中的行实时显示**活动摘要**（最新回复文本或最后一次工具调用，流光徽章标注，约 3 秒刷新）
- **嵌入对话**：点击行 → 面板内直接渲染该子代理的对话，**主会话视图保持不变**；`/side` 可续聊的子代理底部有**输入框**，Enter 直接继续侧聊；`/btw` 一次性子代理为只读视图。对话按**小窗口向后翻页**读取，遇到 fork 种子边界即截断——父会话历史再长，面板也只拉取子会话自身的那一小段
- **面板宽度**：左缘手柄拖拽调宽（320px–55% 屏宽，宽度持久化）、双击手柄复位、⛶ 一键展开到约 75% 屏宽；`Ctrl/Cmd+Shift+E` 开关整个面板
- **Markdown 渲染**：对话中的表格、代码块、列表、公式等按 Markdown 渲染，与主会话一致；运行中流式渲染，结束后定格（语法高亮、公式落地）
- **实时更新**：子代理运行中面板自动刷新其对话，结束后定格最终结果
- **自动弹出**：`/side` 或 `/btw` 命令成功后自动弹出面板并选中新线程
- 手动刷新、错误重试、空态提示一应俱全；「返回列表」回到目录

> 面板列出的是当前会话的**全部直接子代理**——既包括 `/side`、`/btw` 创建的线程，也包括平台或模型在后台创建的（它们同样在后台自主运行）。面板只在点击选中某线程时才显示其对话。

## 主会话隔离

- 侧会话的对话内容（消息/工具/回答）只写入**子会话自己的日志**，不进入主会话的模型上下文（`deriveMessages` 不包含子会话事件）
- 主会话历史里只有两条命令卡片（`Side conversation started: <uuid>.` / `BTW question started: <uuid>.`）；两个命令都配置了 `recordInput: false`，问题正文不会持久化进主会话日志
- 平台会在子代理结算时向父会话投递结算通知；本插件在父代理的 inbox 入口前**静默自家子代理的结算通知**（子代理 id 注册表持久化在 `$DSH_HOME/sidechain-children.json`，重启后依然生效），因此通知、空 turn 和回答都不会写入主会话日志

## 验证

1. `/btw 1+1=?` → 命令立即返回、主会话输入保持可用；侧链面板自动弹出并流式显示该侧问的完整对话与答案，主会话保持原样。
2. `/side 检查一下当前工作区状态` → 面板弹出并实时显示侧线程执行过程，主会话继续正常干活。
3. 在面板里对 `/side` 子代理输入新消息 → 侧线程继续回答，主会话不受影响。
4. 重启 `dsh web` 后打开侧链面板，历史线程的对话从持久化日志恢复；重启前创建的侧线程结束后也不会唤醒主会话。

## 已知限制

- fork 只继承父会话**已完成回合**；进行中的回合不包含。
- `/side` 必须带首个问题；宿主没有「只创建不提交 prompt」的能力，因此插件不会用伪造的等待消息浪费一次模型调用。
- `/btw` 是一次性运行，无后续轮次；多轮侧聊请用 `/side`。
- `/side list` 列出的是本会话全部直接子代理（含平台/模型委派的），不限于侧会话。
